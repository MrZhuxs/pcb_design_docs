这一章是本笔记的**阶段性终局**：前面所有章节讲的东西——叠层、阻抗、参考平面、等长、电源完整性、上电时序、Bring-up 调试——在这里**必须同时成立**。

目标很明确：**做出一块能装上 Ubuntu 22、从 NVMe 启动、接口全部可用的迷你主机主板。**

<Callout type="info" title="这不是练习题，是考核题">
练习题允许你只验证一个知识点。这块板不允许——
DDR 训练失败，板子不起；电源时序错，板子不起；参考平面被割断，DDR 跑不稳。
**任何一环出问题，整块板归零。这就是它作为考核的意义。**
</Callout>

## 一、项目定位与验收标准

### 项目目标

| 项目 | 内容 |
| --- | --- |
| 产品形态 | 紧凑型迷你主机主板（板载 CPU、板载内存、M.2 存储） |
| 计算平台 | 瑞芯微 **RK3588**（4×A76 + 4×A55，8nm） |
| 内存 | **板载 LPDDR4X**（16bit × 2 通道） |
| 存储 | **M.2 M-Key**，PCIe 3.0，NVMe SSD |
| 操作系统 | **Ubuntu 22.04**（单一目标，不含 Windows） |
| PCB | **6 层**，无 HDI 盲埋孔（通孔工艺） |
| 接口规模 | **7 项必需 + 3 项可选**（见第五章） |

### 验收标准（全部满足才算通过）

<Callout type="success" title="通过判据">
1. **上电启动**：串口输出完整启动日志，日志中打印的内存容量与实际焊接一致
2. **存储启动**：能从 M.2 NVMe 上的 Ubuntu 22.04 正常启动到桌面
3. **显示输出**：HDMI 输出可用，分辨率与刷新率达到设计目标
4. **外设可用**：2× USB 3.1 均能识别 U 盘并达到 USB 3.0 速率（非降级到 USB 2.0）
5. **电源达标**：各路电源纹波 < 50mV、上电时序符合顺序要求
6. **热稳定**：满载连续运行 1 小时不降频、不死机、温度在限值内
7. **可复现**：全部设计文件（原理图 / PCB / 叠层 / 规则 / BOM / Gerber）归档完整
</Callout>

<Callout type="warn" title="判据 4 是最容易被忽略的一条">
USB 3.1 的差分对阻抗若偏离 90Ω、或 AC 耦合电容摆放不当，**链路会静默降级到 USB 2.0**——
设备照样能用，但速率掉一个数量级。**必须用速率实测来判定，不能只看“能识别”。**
</Callout>

<Callout type="info" title="这七条是“及格线”，不是计分方式">
上面是**是否通过**的最低门槛。**具体每一项值多少分、怎样拿满、什么情况直接不合格**，
见下一章 [评分标准](#评分标准)——**建议动手前先读评分表**，它会直接指导你的设计取舍。
</Callout>

## 二、评分标准

这是本章的**判分依据**。先把评分要求定在这里，再看架构与设计——这样每个设计决策都能对应到明确的考核指标，而不是事后补分。

**总分 100 分 = 必得项 92 分 + 加分项（上限 8 分）**

<Callout type="warn" title="评分的前提：分数只认实测证据">
每一项的判据都是**可测量、可复核**的（示波器读数、速率测试、日志、DRC 报告、X-ray 图）。
自检记录也可以，但**"我觉得可以"不计分**。
所以建议从一开始就**同时写测试记录**——分数是结果，记录才是依据。
</Callout>

### 2.2 门槛项（导致不合格）

以下任一项不通过，**无论其他项得多少分，判定不合格**：

| 门槛项 | 说明 |
| --- | --- |
| ❌ **任何一路电源对地短路** | 上电即烧板，属致命设计错误 |
| ❌ **DDR 无法训练 / 内存不识别** | 板子根本不起，项目不成立 |
| ❌ **系统无法启动（连串口输出都没有）** | 无任何可验证成果 |

<Callout type="warn" title="为什么门槛项这么严">
因为这三项**不是"扣分项"，而是"项目是否存在"的问题**。
一块短路烧掉的板、一块内存不识别的板、一块串口都没输出的板——
无论 DRC 多干净、文档多完整，它**都不是一台迷你主机**。
</Callout>

| 加分项 | 分值 | 说明 |
| --- | --- | --- |

| 输出正确且不降低可制造性 | +2 | 如在不增加层数前提下优化布线 |

**加分项合计上限 8 分**，总分不超过 **100 分**。

### 平台选型理由

选择 RK3588 而不是 x86 平台，**不是因为性能，而是因为"资料可得性"**：

| 关键因素 | RK3588 | x86 移动 SoC |
| --- | --- | --- |
| 引脚级 datasheet | ✅ 原厂公开 | ❌ NDA 资料，个人拿不到 |
| 参考原理图 / PCB | ✅ 原厂设计资料公开流通 | ❌ 不公开 |
| 内存初始化代码 | ✅ 厂商提供（打包在 loader） | ❌ MRC 闭源，需签约 |
| 固件 | ✅ U-Boot 开源 | ❌ UEFI 闭源 |
| 运行 Ubuntu 22 | ✅ 成熟 | ✅ |

<Callout type="idea" title="这个选择的本质">
**x86 方案卡住的不是画板能力，而是拿不到芯片资料和固件。**
换到 RK3588，你就从"猜引脚、猜初始化参数"变成"**照着原厂参考设计做**"——
这是这个项目唯一可行的前提。
</Callout>

### 为什么只做 7 个接口

这是一次**主动的减法**，不是遗漏。原需求中的无线网、音频、有线网、Type-C 全部砍掉，理由：

| 被砍接口 | 砍掉的理由 |
| --- | --- |
| **M.2 E-Key 无线网** | 需额外 PCIe x1 + USB2 + 天线馈线，6 层通道不够分配 |
| **有线以太网** | RGMII/SGMII 需专用走线通道，与 DDR 争抢 L1/L6 |
| **音频 Codec** | 涉及模拟地分割，会破坏 L2/L5 完整平面（本方案的命脉） |
| **Type-C（DP Alt + PD）** | PD 协议 + CC 逻辑 + 高密度布线，工作量与考核价值不匹配 |

<Callout type="warn" title="务必守住这条纪律">
**砍接口是 6 层方案能成立的前提。** 一旦往回加接口，就必须升到 8 层——
否则 DDR 的参考平面会被迫让步，板子直接起不来。
**接口是软约束，DDR 是硬门槛。**
</Callout>

## 四、内存方案与供应链风险

### 为什么是 LPDDR4X

选"便宜、够用"的内存，在 RK3588 上**只有 LPDDR 系列可选**——它**不支持标准 DDR4**：

| 内存 | RK3588 支持 | 相对成本 | 供应状况 |
| --- | --- | --- | --- |
| **LPDDR4X** ← 本方案 | ✅ | **最低** | ⚠️ 正在停供，需注意料况 |
| LPDDR4 | ✅ | 略高 | 老料 |
| LPDDR5 | ✅（最大 8GB） | 最高 | 在产，最稳 |

### DDR 专项配置

| 项目 | 配置 | 说明 |
| --- | --- | --- |
| 位宽 | **16bit × 2 通道**（共 32bit） | 单通道省层数但带宽腰斩，不作为首选 |
| 容量 | 8GB（2×4GB 颗粒） | 视料况可降为 4GB |
| 速率 | 由原厂初始化参数决定 | **不自选速率**，跟随参考设计 |
| 拓扑 | **复刻原厂**（Fly-by 或 T 型，按参考设计） | 不可自行更改 |

<Callout type="warn" title="复刻铁律">
DDR 部分**只做一件事：高保真复刻原厂参考设计**。

**原因**：瑞芯微的 DDR 初始化参数（时序、延时、驱动强度）是**按原厂参考设计的叠层、阻抗、走线长度调出来的**。
你一旦改动，参数即失效：

```text
原厂参考设计（N 层） → 叠层 → 初始化参数 → 能启动
        ↓ 你改动叠层 / 拓扑 / 颗粒型号
   参数不再适配 → 内存训练失败 → 板子不起
```

**你无法自行生成新参数**，这项适配需要原厂支持。
所以：**叠层、阻抗、等长规则、拓扑——照抄。外围接口才自主设计。**
</Callout>

### 采购与验料

LPDDR4X 处于停产过渡期，**必须提前锁料**：

- 优先选用**明确在产**的颗粒型号，索要原厂 datasheet 与 PCN（产品变更通知）
- 警惕拆机料：外观有植球痕迹、批次混乱、无原厂包装的，一律不用
- **先买 2 倍用量的料**（焊接损耗 + 万一损坏）
- 焊接前确认颗粒的**封装代码与球位定义**与参考设计一致

## 六、叠层与设计规则

### 6 层叠层方案

这是全章**最关键的一张表**。常规 6 层板在这里会失败，必须用下面的对称叠层：

| 层 | 用途 | 参考平面 | 说明 |
| --- | --- | --- | --- |
| **L1** | 信号 | L2 (GND) | **DDR 主体**、PCIe、USB3、HDMI |
| **L2** | **GND 完整** | — | **不分割**，全板第一参考面 |
| **L3** | 信号 / 电源铜皮 | L2 / L4 | **只走低速**，因夹在两平面之间 |
| **L4** | **PWR 单一主轨** | — | 只放**一个**主电源（如 VDD_CPU 0.8V） |
| **L5** | **GND 完整** | — | 第二参考面，缩短回流路径 |
| **L6** | 信号 | L5 (GND) | DDR 剩余 + 接口 + 背面器件 |

<Callout type="warn" title="L4 绝对不能分割——这是 6 层方案的命脉">
常规做法是把 L4 割成 0.8V/1.1V/1.8V/3.3V/5V 多路。**在本方案里这是致命的**：

- L3 上的走线**下方就是 L4**，L4 一旦分割，L3 走线跨越分割缝时**参考平面断裂**
- 阻抗随之跳变 → 反射、辐射、时序失控

**所以：用一个完整电源平面，换全部信号的参考完整性。**
其余电源轨走 L3/L6 铜皮 + 就近去耦电容补偿。**顺序不能颠倒。**
</Callout>

### 阻抗控制目标

| 信号类型 | 目标阻抗 | 容差 | 走线层 |
| --- | --- | --- | --- |
| 单端通用信号 | 50Ω | ±10% | L1 / L6 |
| **DDR**（按原厂要求） | 跟随参考设计 | 严格 | L1 / L6 |
| **PCIe 3.0** | 85Ω 差分 | ±10% | L1 |
| **USB 3.1** | 90Ω 差分 | ±10% | L1 |
| **HDMI 2.1** | 100Ω 差分 | ±10% | L1 |

<Callout type="info" title="微带线只在外层">
本方案只有 L1、L6 是"紧贴完整 GND 的微带线"，因此**所有阻抗敏感信号都必须走这两层**。
L3 只承担低速与电源分配。**这是 6 层方案的必然结果，不是偏好。**
</Callout>

### 通用设计规则

| 规则 | 取值 | 适用范围 |
| --- | --- | --- |
| 最小线宽 / 间距 | 4 mil / 4 mil | 通用 |
| 差分对内间距 | 按阻抗计算 | 差分对全程等距 |
| 差分对内等长 | ≤ 5 mil | PCIe / USB3 / HDMI |
| 差分对间间距 | ≥ 5× 线宽（5W） | 抑制串扰 |
| DDR 等长 | **按原厂参考设计** | 数据组内 / 地址组内 |
| 过孔 | 通孔，孔径按板厂能力 | 无盲埋孔（降成本） |
| 高速信号换层次数 | ≤ 2 次 | 每次换层配回流地过孔 |
| 晶振 / 参考时钟 | 包地 + 禁布区 | 远离开关电源≥ 5mm |

## 七、DDR 专项设计

### 参考平面策略

DDR 的成败**几乎完全取决于参考平面**。本方案的做法：

- DDR 信号**全部走 L1 / L6**，各自紧贴 L2 / L5 完整 GND
- **任何 DDR 走线不得跨越平面缝隙**——L2/L5 是全板完整平面，天然满足
- **禁止在 DDR 走线区域下方开槽**（包括为了给别的信号让路而挖的洞）
- DDR 换层时，**每个信号过孔旁 0.5mm 内加一个回流地过孔**
- DDR 电源（1.1V / 0.6V）由 L3 铜皮带过去，**并在颗粒下方铺满去耦电容**

### 等长与拓扑规则

**跟随原厂参考设计**，通常遵循：

| 组别 | 等长要求 |
| --- | --- |
| 数据组（DQ / DQS / DMI） | 组内严格等长，DQS 与 DQ 差控制在极小范围 |
| 时钟与选通 | 优先等长，按参考设计相对延时 |
| 地址 / 命令 / 控制 | 组内等长，与时钟的时序关系按参考设计 |
| 通道间（CH0 / CH1） | 两条通道各自独立等长 |

<Callout type="warn" title="不要自行优化">
原厂参考设计给出的等长数值、拓扑形状（Fly-by / T 型）、走线顺序，**都是初始化参数的组成部分**。
你觉得“这样绕太长、改直一点更好看”的每一次改动，都可能让内存训练失败。
**DDR 部分不需要你的创造力，需要你的忠实。**
</Callout>

## 八、电源设计

### 电源树

| 电源轨 | 电压 | 供给对象 | 实现方式 | 备注 |
| --- | --- | --- | --- | --- |
| VIN | 12V | 输入 | 外部适配器 | 9–20V 宽压 |
| VSYS | 5V | 主降压输出 | **Buck，大电流** | 主要功率通道 |
| 3V3 | 3.3V | 系统 / 外设 | Buck | — |
| 1V8 | 1.8V | IO / DDR IO | Buck | 噪声敏感 |
| VDD_CPU | 0.8V | CPU / GPU / NPU | Buck，**多相** | 最大电流轨 |
| VDD_DDR | 1.1V | DDR 颗粒 | LDO / Buck | 纹波要求最严 |
| VDDQ_DDR | 0.6V | DDR IO | LDO | 与 1.1V 配对 |

<Callout type="info" title="电压值以最终选定的参考设计为准">
上表是 RK3588 平台的**典型值**，用于说明结构。
**实际取值、电流预算、时序要求必须以原厂硬件设计指导书为准**——不同配置（核心频率、DDR 代数）会有差异。
</Callout>

### 上电时序

```text
 12V 输入
   ↓
 5V 主轨 ──→ 3.3V ──→ 1.8V IO ──→ 1.1V DDR ──→ 0.6V VDDQ ──→ 0.8V VDD_CPU
                                                                    ↓
                                                          释放复位 → 启动固件
```

**要点**：

- 严格按**参考设计给出的顺序与延时**实现，用 PGOOD 信号级联或专用时序控制
- **核心电压最后上**（避免 IO 先有电、核心未就绪导致闩锁）
- 每一路的 PGOOD 都要参与下一级的使能，**不能只靠 RC 延时**
- 上电顺序错误可能**直接损坏芯片**，不是"跑不稳"这么轻

### M1 子项目：独立电源板

<Callout type="idea" title="强烈建议先做一块独立的电源板">
**把电源部分单独做成一块小板先验证**，而不是和主板一起打样。

理由：电源是**所有问题的共同嫌疑犯**。如果电源和主板在同一块板上，
板子不起时你无法判断是"电源没做好"还是"DDR 布错了"。
**把变量分开，是 Bring-up 的第一原则。**
</Callout>

**M1 验收**：各路输出电压在 ±3% 内、纹波 < 50mV、上电时序符合顺序、可带载 30W 不跌落。

## 十、Bring-up 与故障排查

### 上电第一原则

<Callout type="warn" title="上电前的三个必做动作">
1. **测电源对地阻值**——任何一路短路都必须先查清，否则上电即烧板
2. **限流上电**——用可调电源，起始电流限值设为目标值的 30%
3. **先空载、后带载**——先确认电源正常，再插 M.2、再连外设

**违反其中任何一条，都可能让几个月的成果在 1 秒内报废。**
</Callout>

### 三层排查法

故障排查的通用模型是：**症状 → 测量 → 可能原因**。只描述症状无法定位，必须落到可测量的量。

#### 串口完全无输出

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 用示波器测 UART TX 引脚，看是否有波形（而不是只看有没有电压）
- 测各路电源的**实际电压与纹波**
- 测复位引脚电平：是否一直被拉低
- 测晶振：是否起振（示波器 + 探头电容要小，避免停振）

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 电源时序错误，核心未上电 | 逐路测电压与 PGOOD |
| 复位一直被拉低 | 测复位网络，查上拉电阻与电容 |
| 晶振未起振 / 负载电容选错 | 换探头再测，核对负载电容值 |
| 固件（SPI Flash）没烧或烧错 | 读回 Flash 内容比对 |
| UART 波特率不匹配 | 确认 RK3588 启动串口的默认波特率 |
| BGA 虚焊 | X-ray 复查，或补焊 |

</details>

#### DDR 内存训练失败 / 容量不对

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 读启动日志中 DDR 训练的报错信息（哪个通道、哪个字节出错）
- 实测 VDD_DDR（1.1V）与 VDDQ（0.6V）的纹波——**纹波是首要嫌疑**
- 抽查 DDR 走线的实际长度是否与设计一致

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| **叠层或阻抗偏离原厂参考设计** | 对比实际叠层与参考设计，用阻抗测试条验证 |
| DDR 走线等长未按规则 | 回 PCB 工具检查等长报告 |
| 参考平面跨分割 | 检查 L2/L5 是否有开槽或被其他信号切断 |
| 电源纹波过大 / 去耦不足 | 实测颗粒下方电源纹波，检查去耦布局 |
| 换层未配回流过孔 | 数一数 DDR 过孔旁有没有地过孔 |
| 颗粒型号与参考设计不一致 | 核对封装代码与球位定义 |

**这是最可能卡住的一关**，也是 6 层方案的主要风险点。见第十一章降级预案。

</details>

#### NVMe（M.2）不识别

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 测 M.2 插槽供电（3.3V）是否正常、是否带载跌落
- 测 PCIe 参考时钟是否起振、频率是否正确
- 示波器看 TX 差分对是否有信号输出

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| PCIe 差分阻抗偏离 85Ω | 用阻抗测试条验证 |
| AC 耦合电容缺失 / 位置错误 | 核对原理图，电容应靠近发送端 |
| 参考时钟未起振 | 测时钟输出 |
| 复位 / 供电时序不对 | 测插槽供电与复位信号 |
| 差分对内未等长、对间串扰大 | 检查等长报告与间距规则 |
| 通道未被固件使能 | 查设备树 / 固件配置 |

</details>

#### USB 3.1 降级到 USB 2.0

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- **实测传输速率**（必须，不能只看"能识别"）
- 测 90Ω 差分阻抗
- 检查 AC 耦合电容与共模电感

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 差分阻抗偏离 90Ω | 阻抗测试条验证 |
| 差分对未等长、未等距 | 检查走线规则 |
| AC 耦合电容容值错 / 摆放错 | 核对原理图与布局 |
| VBUS 供电在带载时跌落 | 测带载时 VBUS 电压 |
| ESD 器件寄生电容过大 | 换低电容 ESD 器件 |

</details>

#### HDMI 无输出 / 花屏

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 测 HPD（热插拔检测）信号是否有响应
- 测 TMDS 差分对是否有信号
- 检查 DDC（I²C）通信是否正常

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 100Ω 差分阻抗偏离 | 阻抗测试条验证 |
| HPD / DDC 上拉缺失 | 核对原理图 |
| ESD 器件影响高速信号 | 换低电容器件 |
| 差分对间串扰过大 | 检查 5W 间距规则 |
| 连接器焊接不良 | 目检 + 通断测试 |

</details>

## 十一、降级预案

这是本章最实用的一节。**6 层 + 板载 LPDDR4X 是一次高风险尝试**——有依据：

<Callout type="warn" title="风险有原厂数据支撑">
TI 的 [LPDDR4 设计指南](https://www.ti.com/lit/pdf/spracn9)实测显示：
**10 层**参考设计可跑到 **4266 Mbps**，而**8 层**设计**只达到 3733 Mbps**，
原厂明确说明原因是"**层数受限带来的设计妥协（实心参考平面等）**"。

连原厂团队在 8 层板上都要妥协、掉速。**6 层是这条曲线更往下的一步，必须有心理准备。**
</Callout>

### 降级顺序（不要搞错优先级）

当 M3 布线阶段发现通道不够、或 M5 出现 DDR 训练失败时，**按下面的顺序处理**：

| 优先级 | 措施 | 代价 | 何时采用 |
| --- | --- | --- | --- |
| **1** | **升到 8 层** | 打样成本上升 | **首选**——DDR 启动是硬门槛 |
| **2** | 放弃可选接口（USB2.0 / 前面板 / RTC） | 功能减少 | 升级层数后仍紧张 |
| **3** | 内存容量降级（8GB → 4GB） | 性能下降 | 单颗容量版本更易采购时 |
| **4** | 内存改单通道（16bit × 1） | **带宽腰斩** | 实在挤不下时，最后手段 |
| ❌ | 改 DDR 拓扑或叠层去"优化" | **大概率板子不起** | **绝不允许** |

<Callout type="idea" title="为什么不先砍接口，而是先升层数">
因为**砍接口救不了 DDR**。DDR 训练失败的原因是叠层与参考平面，而 6 层已经用尽了叠层手段，
再砍接口也无法给 DDR 腾出"紧贴完整 GND 的信号层"。

而升级到 8 层可以增加独立信号层与参考平面，**直接解决根因**。
**接口是软约束，层数是硬约束——硬约束优先。**
</Callout>

### 如果最终无法通过

即使这块板最终没能启动，**这个项目依然完成了考核**，因为你必须亲手经历：

- 叠层设计如何决定阻抗与参考平面
- DDR 等长与拓扑为什么不能随意"优化"
- 电源时序错误如何让整板归零
- Bring-up 时如何用有限的仪器把故障范围逐层缩小
- 为什么"能画出来"和"能量产、能启动"是两件事

<Callout type="success" title="考核的真正目的">
这份蓝图的验收标准写得苛刻，但它的价值不在"板子亮不亮"，
而在**你有没有建立起工程判断力**：
知道哪个约束是硬的、哪个是软的，知道出问题时先怀疑什么、先测量什么。

**这正是序章里那句"能量产、能过认证、能稳定跑五年的板"的真正含义。**
</Callout>
