## 一、产品定位与规格

### 1.1 它是什么

面向**嵌入式、AIoT、工业控制**场景的 ARM 开发套件，主控是瑞芯微 **RK3568**（四核 Cortex-A55）。

它的产品逻辑是"**核心板负责算力，底板负责接口**"：

| 部分 | 尺寸 | 承担什么 | 谁设计 |
| --- | --- | --- | --- |
| **核心板（SoM）** | **65 mm × 50 mm** | RK3568、DDR4、eMMC、PMIC、板对板连接器 | 模组/原厂 |
| **底板（Carrier）** | **100 mm × 90 mm** | 电源输入、双网口、PCIe、HDMI、Type-C、调试口 | **本项目的主体** |

<Callout type="idea" title="为什么这套件值得当「终章」">
因为它把"**你只能在底板上下手**"这个真实约束摆在面前：
核心板的 DDR 布线你不必负责，但**你要为核心板供好电、把高速信号干净地引出去**——
这正是绝大多数工程师真正的工作内容。
</Callout>

## 二、验收标准与评分

### 2.1 通过判据（全部满足才算通过）

<Callout type="success" title="通过判据">
1. **上电启动**：调试串口输出完整启动日志，无卡死、无重启循环
2. **系统可用**：Android 或 Linux（Debian / Ubuntu / Buildroot + Qt 任选其一）能正常进入系统
3. **双网口**：两个 RJ45 均能链路上行，**协商到 1000 Mbps**，双向 iperf3 速率达标
4. **PCIe 3.0**：能识别 M.2 NVMe 固态硬盘，读写速率不出现"降级到 PCIe 1.1/2.0"的现象
5. **显示输出**：HDMI 2.0 输出正常，分辨率与刷新率达到设定目标，无花屏、无闪屏
6. **三路 Type-C**：全部可识别设备，其中 USB 3.0 那一路**实测达到 5 Gbps 档速率**（不能只看"能认到盘"）
7. **电源达标**：各路输出电压在 ±5% 内、纹波在限值内，上电时序正确、可重复上电 100 次不异常
8. **可复现**：原理图 / PCB / 叠层 / 规则 / BOM / Gerber / 测试记录归档完整
</Callout>

<Callout type="warn" title="判据 6 是最容易被糊弄过去的一条">
Type-C 的 USB 3.0 若差分阻抗偏离 90Ω、或 AC 耦合电容位置不对，**链路会静默降级到 USB 2.0**——
盘照样能读，速率掉一个数量级，而你在"设备管理器"里看不出任何异常。
**必须用实测速率判定，不能只看"能识别"。**
</Callout>

### 2.2 门槛项（任一项不通过即判定不合格）

| 门槛项 | 说明 |
| --- | --- |
| ❌ **任何一路电源对地短路** | 上电即烧板，属致命设计错误 |
| ❌ **核心板供电异常 / 无法启动** | 5V 主轨跌落、时序错乱，板子根本不起 |
| ❌ **调试串口无任何输出** | 失去唯一观测手段，项目不成立 |

<Callout type="warn" title="门槛项不是「扣分项」">
一块短路烧掉的板、一块起不来的板、一块串口都没输出的板——
无论 DRC 多干净、文档多完整，它**都不是一块开发套件**。
**这三条决定"项目是否存在"，其余决定"项目有多好"。**
</Callout>

### 3.2 100 × 90 mm 的分区

板上面积只有 90 cm²，扣掉核心板的 32.5 cm²，留给接口的只有一半多。**先分区，再画原理图**：

| 区域 | 内容 | 关键约束 |
| --- | --- | --- |
| **中央偏上** | 核心板（65 × 50 mm） | 板对板连接器位置决定所有高速信号的出口方向 |
| **左侧板边** | 双 RJ45 + 网络变压器 | 变压器与连接器距离尽量短，网口侧做 Bob Smith 端接与机壳地 |
| **右侧板边** | HDMI + Type-C ×3 | 连接器靠近板边，ESD 器件紧贴连接器 |
| **下侧板边** | DC 输入 / 电源区 / 按键 / LED | 大电流路径短而宽，远离高速区 |
| **靠近核心板** | PCIe 3.0 通道 → M.2 座 | 差分对路径最短化，避免跨分割 |
| **边角** | 调试串口排针、风扇 4-pin、TF 卡槽 | 便于接线与测量 |

<Callout type="warn" title="布局顺序错了，后面全是补救">
**正确顺序：核心板位置 → 高速接口连接器位置 → 电源区 → 低速与调试**。
反过来做（先把电源和按键摆满，再挤高速口）会得到一条必然跨分割的 PCIe 通道，
而**跨分割是这一版无法靠布线技巧弥补的硬伤**。
</Callout>

### 3.3 核心板与底板的信号预算

板对板连接器是这套架构的**唯一瓶颈**，引脚预算必须提前算：

| 信号组 | 大致数量级 | 说明 |
| --- | --- | --- |
| 双 RGMII（数据 + 时钟 + 控制） | 2 × 12 根左右 | 单口 RGMII 约 12 根（4 数据 × 双向 + 时钟 + 控制） |
| PCIe 3.0 | 2 根差分（TX）+ 2 根差分（RX）+ 参考时钟 | 加复位与电源使能 |
| HDMI 2.0 | 4 对差分 + DDC + HPD + CEC | 差分对内等长是硬要求 |
| Type-C ×3 | USB3 差分对 + USB2 差分对 + CC + VBUS 检测 | 每路都要独立 VBUS 开关与限流 |
| 电源 | 5V / 3.3V / 1.8V / GND | **大电流引脚要冗余并联，不能只靠一根** |

<Callout type="info" title="连接器引脚不够，是这类项目最常见的返工原因">
一旦高速信号被迫从连接器的**不同排、不同层**引出，等长和参考平面就同时失控。
**在画原理图之前，先拿着连接器 pinout 把上表逐项"占位"排一遍**，比事后改板便宜得多。
</Callout>

### 4.2 三路 Type-C 的职能分配

三路 Type-C 挤在 100 mm 板边上，**必须先定义清楚再画图**，否则会出现"物理接口有三个、可用能力只有一个"：

| 编号 | 建议职能 | 关键设计 |
| --- | --- | --- |
| **C1** | **USB 3.0 OTG / 主机** | 差分对 90Ω，AC 耦合电容靠发送端；CC 逻辑支持 OTG 角色识别 |
| **C2** | **USB 2.0 主机（外设）** | 90Ω 差分，VBUS 加限流开关，ESD 贴连接器 |
| **C3** | **调试 / 供电** | 若含 USB-UART，注意串口电平与地；若支持 PD 供电，需协议芯片与路径管理 |

<Callout type="warn" title="以最终原理图与参考设计为准">
上表是**蓝图阶段的职能分工建议**，真实分配取决于核心板引出的 USB 通道数量与 PMIC 的供电能力。
**先按这个分工排布机械结构与连接器位置，再回头核对原厂参考设计**——
顺序反过来，往往要在改板时重排整条板边。
</Callout>

没有它，板子不启动时你只能猜。**必须在第一版就留出来。**
</Callout>

## 五、内存与存储

### 5.1 为什么是 DDR4，不是 LPDDR

这颗 SoC 同时支持 DDR4 与 LPDDR4/4X，选 **DDR4** 的核心理由是**供应链与可维修性**：

| 方案 | 优势 | 代价 |
| --- | --- | --- |
| **DDR4（本方案）** | 料源多、单价低、国产替代充分（长鑫） | 颗粒体积大，走线更长，需要更严格的等长 |
| LPDDR4X | 体积小、功耗低、适合手持 | 焊接与返修困难，料况波动大 |

### 5.2 DDR4 8Gbit 的容量账

**CXDQ3BFAM-CQ-A 是一颗 8 Gbit 的 DDR4 颗粒**：

| 项 | 数值 |
| --- | --- |
| 单颗容量 | **8 Gbit = 1 GB** |
| 颗粒位宽 | x16（以 datasheet 为准） |
| 单颗方案 | 1 GB 系统内存 |
| 双颗方案 | 2 GB 系统内存（需要足够的通道与等长预算） |

<Callout type="warn" title="复刻铁律：DDR 部分不要发挥创造力">
DDR 的初始化参数（时序、延时、驱动强度）是**按原厂参考设计的叠层、阻抗、走线长度**调出来的。
你一旦改动叠层或拓扑，参数即失效：

<FlowChart title="改一个叠层参数，为什么板子就起不来">
  <FlowNode label="原厂参考设计" sub="叠层、拓扑、颗粒型号都对得上" />
  <FlowArrow label="参数匹配" />
  <FlowNode label="初始化参数可用" sub="内存训练通过 → 正常启动" accent />
  <FlowArrow label="你改动了叠层 / 拓扑 / 颗粒型号" />
  <FlowNode label="参数不再适配" sub="内存训练失败 → 板子不起" />
</FlowChart>

**DDR 部分只做一件事：高保真复刻原厂参考设计。** 外围接口才是你自主设计的战场。
</Callout>

### 5.3 采购与验料

- 优先选用**明确在产**的颗粒型号，索要原厂 datasheet 与 PCN（产品变更通知）
- 警惕拆机料：有植球痕迹、批次混乱、无原厂包装的一律不用
- **先买 2 倍用量的料**（焊接损耗 + 万一损坏）
- 焊接前核对颗粒的**封装代码与球位定义**与参考设计一致

## 六、叠层与阻抗

### 6.1 6 层叠层方案

常规 6 层板在这里会失败，必须用下面的对称叠层（1.6 mm 板厚）：

| 层 | 用途 | 参考平面 | 说明 |
| --- | --- | --- | --- |
| **L1** | 信号 | L2 (GND) | **PCIe / USB3 / HDMI / RGMII** 主体 |
| **L2** | **GND 完整** | — | **不分割**，全板第一参考面 |
| **L3** | 信号 / 电源铜皮 | L2 / L4 | **只走低速**，因夹在两平面之间 |
| **L4** | **PWR 单一主轨** | — | 只放**一个**主电源（如 5V 或 3.3V） |
| **L5** | **GND 完整** | — | 第二参考面，缩短回流路径 |
| **L6** | 信号 | L5 (GND) | 剩余接口信号 + 背面器件 |

<Callout type="warn" title="L4 绝对不能分割——这是 6 层方案的命脉">
常规做法是把 L4 割成 5V / 3.3V / 1.8V 多路。**在本方案里这是致命的**：

- L3 上的走线**下方就是 L4**，L4 一旦分割，L3 跨分割运行时**参考平面断裂**
- 阻抗随之跳变 → 反射、辐射、时序失控

**所以：用一个完整电源平面，换全部信号的参考完整性。**
其余电源轨走 L3 / L6 铜皮 + 就近去耦补偿。**顺序不能颠倒。**
</Callout>

### 6.2 阻抗控制目标

| 信号类型 | 目标阻抗 | 容差 | 走线层 |
| --- | --- | --- | --- |
| 单端通用信号 | 50Ω | ±10% | L1 / L6 |
| **PCIe 3.0** | **85Ω 差分** | ±10% | L1 |
| **USB 3.0（Type-C）** | **90Ω 差分** | ±10% | L1 |
| **HDMI 2.0** | **100Ω 差分** | ±10% | L1 |
| **千兆网 RGMII 差分** | **100Ω 差分** | ±10% | L1 / L6 |
| RGMII 单端数据 / 时钟 | 50Ω | ±10% | L1 / L6 |

<Callout type="info" title="微带线只在外层">
本方案只有 L1、L6 是"紧贴完整 GND 的微带线"，因此**所有阻抗敏感信号都必须走这两层**。
L3 只承担低速与电源分配。**这是 6 层方案的必然结果，不是偏好。**
</Callout>

### 6.3 通用设计规则

| 规则 | 取值 | 适用范围 |
| --- | --- | --- |
| 最小线宽 / 间距 | 4 mil / 4 mil | 通用 |
| 差分对内间距 | 按阻抗计算 | 差分对全程等距 |
| 差分对内等长 | ≤ 5 mil | PCIe / USB3 / HDMI |
| 差分对间间距 | ≥ 5 × 线宽（5W） | 抑制串扰 |
| RGMII 组内等长 | 按 PHY 手册（通常 ≤ 500 mil 量级） | 时钟与数据组 |
| 过孔 | 通孔，孔径按板厂能力 | 无盲埋孔（降成本） |
| 高速信号换层次数 | ≤ 2 次 | 每次换层配回流地过孔 |
| 晶振 / 参考时钟 | 包地 + 禁布区 | 远离开关电源 ≥ 5 mm |
| AC 耦合电容 | **靠近发送端** | PCIe / USB3 / HDMI |

## 七、电源与上电时序

### 7.1 电源树

底板只负责"把 12V 变成干净的 5V / 3.3V / 1.8V"，**核心电压由核心板上的 PMIC 生成**——
这是 SoM 架构最大的好处，也是你必须守住的边界。

| 电源轨 | 电压 | 供给对象 | 实现方式 | 备注 |
| --- | --- | --- | --- | --- |
| VIN | 12V | 输入 | 外部适配器 / Type-C PD | 反接与浪涌保护 |
| **VSYS** | **5V** | 核心板主供电、Type-C VBUS、风扇 | Buck，**大电流** | 主功率通道，纹波最敏感 |
| 3V3 | 3.3V | PHY、连接器、外设 | Buck | 网口与 HDMI 供电 |
| 1V8 | 1.8V | IO 域、部分外设 | Buck / LDO | 噪声敏感 |
| 核内轨 | 由 PMIC 产生 | CPU / GPU / NPU / DDR | 核心板 PMIC | **不在底板设计范围内** |

<Callout type="info" title="电压值以原厂参考设计为准">
上表是 RK3568 平台的**典型结构**，用于说明分工。
**实际取值、电流预算、时序要求必须以原厂硬件设计指导书与核心板规格书为准**——
不同核心板厂商的供电定义会有差异。
</Callout>

### 7.2 上电时序

<FlowChart title="开发套件电源树：12 V 进来，三路出去">
  <FlowNode label="12 V 输入" sub="DC 头 / Type-C PD" accent />
  <FlowArrow label="第一级降压" />
  <FlowNode label="5 V 主轨" sub="核心板、USB、风扇" />
  <FlowBranches>
    <FlowBranch label="3.3 V" sub="PHY 与外设" />
    <FlowBranch label="1.8 V" sub="IO 域" />
    <FlowBranch label="5 V VBUS" sub="Type-C 输出" />
  </FlowBranches>
  <FlowArrow label="各路稳定之后" />
  <FlowNode label="释放核心板复位" sub="启动固件" accent />
</FlowChart>

**要点**：

- 5V 主轨**先行且必须最先稳定**——核心板的 PMIC 依赖它工作
- 用 PGOOD 信号级联，**不要只靠 RC 延时**去凑时序
- 复位信号必须有明确的上拉与滤波，**不能悬空**
- 上电顺序错误可能**直接损坏芯片**，不是"跑不稳"这么轻
- 反复上电 100 次、快速插拔电源，都应能稳定启动

### 7.3 Type-C 与保护

| 项目 | 做法 |
| --- | --- |
| VBUS 输出 | 每路独立限流开关 + 大容量储能电容 |
| CC 逻辑 | 按角色（源/宿）配电阻或协议芯片，**正反插都要能识别** |
| ESD | 连接器紧邻位置放低电容 ESD 器件（差分对寄生电容要小） |
| 反接 / 过压 | 输入端 TVS + 理想二极管或 PMOS 反接保护 |
| 热插拔 | 上电瞬间的浪涌电流不能把 5V 拉跌到核心板复位阈值以下 |

## 八、高速接口专项

### 8.1 双千兆以太网（RGMII）

| 项 | 做法 |
| --- | --- |
| 拓扑 | 两路独立 GMAC → 各自 PHY → 网络变压器 → RJ45 |
| 阻抗 | 差分 100Ω、单端 50Ω |
| 等长 | 时钟与数据组内等长，按 PHY 手册控制 |
| 时钟 | RGMII 的 TX/RX 时钟延时配置必须与 PHY 型号匹配 |
| 变压器 | 靠近 RJ45，初次级之间做隔离与机壳地处理 |
| 端接 | 未用线对做 Bob Smith 端接，抑制共模辐射 |
| 常见坑 | 时钟延时配错 → 链路起但丢包；等长失控 → 高温下掉链 |

### 8.2 PCIe 3.0

| 项 | 做法 |
| --- | --- |
| 阻抗 | **85Ω 差分**，±10% |
| AC 耦合 | 电容靠近**发送端**，容值按规范 |
| 参考时钟 | 100 MHz 差分，走线短、包地、不跨分割 |
| 复位与电源 | PERST# 上拉、M.2 座 3.3V 供电能力要够 |
| 换层 | ≤ 2 次，每次配回流地过孔 |
| 常见坑 | 阻抗偏差 → 链路降到 Gen1；耦合电容位置错 → 时好时坏 |

### 8.3 HDMI 2.0

| 项 | 做法 |
| --- | --- |
| 阻抗 | **100Ω 差分**，四对 TMDS 全程等距等长 |
| ESD | 低电容器件，紧贴连接器 |
| 低速信号 | HPD 上拉、DDC（I²C）上拉、CEC 走线避开高速对 |
| 常见坑 | 差分对内不等长 → 花屏；ESD 寄生电容过大 → 高分辨率下闪屏 |

### 8.4 Type-C / USB 3.0

| 项 | 做法 |
| --- | --- |
| 阻抗 | **90Ω 差分** |
| AC 耦合 | 靠近发送端 |
| 共模 | 必要时加共模电感（注意不能破坏阻抗） |
| VBUS | 大电流路径短而宽，带载压降要实测 |
| 常见坑 | 阻抗偏差或耦合电容位置错 → 静默降级到 USB 2.0 |

## 九、EMC 与热设计

### 9.1 EMC 的三道防线

| 防线 | 措施 |
| --- | --- |
| **源头** | 开关电源环路面积最小、反馈走线远离开关节点、缓启动 |
| **路径** | 完整地平面、换层配回流过孔、高速对远离板边与开槽 |
| **出口** | 网口变压器与 Bob Smith 端接、HDMI / Type-C 的 ESD 与共模抑制、机壳地单点连接 |

<Callout type="warn" title="辐射问题的 90% 在叠层与布局阶段就已决定">
滤波器件只能压住已经跑出板边的那部分能量。
**如果 L4 被割裂、高速对跨了分割、回流被迫绕远路，加多少磁珠都救不回来。**
这就是为什么第六章的叠层规则要放在布线之前定死。
</Callout>

### 9.2 热设计

- 核心板下方留**散热过孔阵列**与铜皮，条件允许时加导热垫到外壳
- 风扇 4-pin PWM 由 SoC 的 PWM 驱动，温度采样取自 SoC 内部传感器或板上 NTC
- **满载 1 小时**是必测项：记录温度、频率、是否降频
- 工业场景要按**环境温度上限**做降额验证，而不是只看室温下的表现

## 十一、Bring-up 与故障排查

### 11.1 上电第一原则

<Callout type="warn" title="上电前的三个必做动作">
1. **测电源对地阻值**——任何一路短路都必须先查清，否则上电即烧板
2. **限流上电**——用可调电源，起始电流限值设为目标值的 30%
3. **先空载、后带载**——先确认电源正常，再插 NVMe、再连外设

**违反其中任何一条，都可能让几个月的成果在 1 秒内报废。**
</Callout>

### 11.2 三层排查法

通用模型是：**症状 → 测量 → 可能原因**。只描述症状无法定位，必须落到可测量的量。

#### 串口完全无输出

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 示波器测调试口 TX，看是否有波形（而不是只看有没有电压）
- 测 5V / 3.3V / 1.8V 的**实际电压与纹波**
- 测核心板复位引脚电平：是否一直被拉低
- 测 PGOOD 是否按时序建立

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 5V 主轨带载跌落 | 带载实测 5V 电压与纹波 |
| 复位一直被拉低 | 测复位网络，查上拉电阻与电容 |
| 上电时序错误 | 逐路测电压与 PGOOD |
| 串口电平不匹配 / 波特率不对 | 换 USB-TTL 模块，试常用波特率（如 1500000） |
| 核心板虚焊或连接器接触不良 | 按压连接器、复查焊接 |

</details>

#### 双千兆网口不通 / 只协商到 100 Mbps

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 看 PHY 的 link LED 与速率 LED
- 读 `ethtool` 的协商结果
- 测 RGMII 时钟是否有输出、频率是否正确

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| **RGMII 时钟延时配置与 PHY 不匹配** | 核对 PHY 手册的 TX/RX delay 配置 |
| 变压器中心抽头供电/端接错误 | 核对原理图与变压器规格 |
| 差分对等长失控 | 回 PCB 检查等长报告 |
| 器件地址 / 设备树配置错误 | 查 dts 中 PHY 地址与 reg |
| 网口侧地处理不当（机壳地与数字地混接） | 复查地与端接方案 |

</details>

#### PCIe 不识别 NVMe

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- `lspci` 是否能看到设备、链路速率与宽度
- 测 M.2 座 3.3V 供电与带载跌落
- 测 100 MHz 参考时钟是否起振

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 差分阻抗偏离 85Ω | 阻抗测试条验证 |
| AC 耦合电容缺失 / 位置错误 | 核对原理图，应靠发送端 |
| PERST# 未释放或上拉缺失 | 测复位信号 |
| 参考时钟未起振 | 测时钟输出 |
| 设备树未使能该控制器 | 查 dts 与固件配置 |

</details>

#### HDMI 无输出 / 花屏

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- 测 HPD 是否有响应
- 测 TMDS 差分对是否有信号
- 检查 DDC（I²C）通信

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 100Ω 差分阻抗偏离 | 阻抗测试条验证 |
| 差分对内不等长 | 检查等长报告 |
| HPD / DDC 上拉缺失 | 核对原理图 |
| ESD 器件寄生电容过大 | 换低电容器件 |
| 连接器焊接不良 | 目检 + 通断测试 |

</details>

#### Type-C 只能跑 USB 2.0 速率

<details>
<summary>展开：测量步骤与可能原因</summary>

**测量**：

- **实测传输速率**（必须，不能只看"能识别"）
- 测 90Ω 差分阻抗
- 检查 AC 耦合电容位置与容值

**可能原因**：

| 原因 | 验证方法 |
| --- | --- |
| 差分阻抗偏离 90Ω | 阻抗测试条验证 |
| 差分对未等长、未等距 | 检查走线规则 |
| AC 耦合电容位置或容值错误 | 核对原理图与布局 |
| CC 逻辑错误导致角色识别失败 | 测 CC 电平 |
| VBUS 带载跌落 | 测带载时 VBUS 电压 |

</details>

## 十二、风险与降级预案

### 12.1 三个真实风险

| 风险 | 表现 | 根因 |
| --- | --- | --- |
| **连接器引脚不够** | 高速信号被迫跨层跨排引出 | M0 阶段没做引脚预算 |
| **L4 被割裂** | PCIe 时好时坏、EMC 超标 | 电源平面被分成多块 |
| **网口时钟延时配错** | 链路起来但丢包 / 速率不稳 | RGMII TX/RX delay 与 PHY 不匹配 |

### 12.2 降级顺序（不要搞错优先级）

发现通道不够、或 M5 出现接口不通时，**按下面的顺序处理**：

| 优先级 | 措施 | 代价 | 何时采用 |
| --- | --- | --- | --- |
| **1** | **升到 8 层** | 打样成本上升 | **首选**——参考平面与通道同时解决 |
| **2** | 放弃可选接口（CSI / 音频 / 扩展排针） | 功能减少 | 升级层数后仍紧张 |
| **3** | 降低接口密度（Type-C 三路改两路） | 功能减少 | 板边空间实在不够 |
| **4** | 内存由双颗改单颗 | 容量腰斩 | 核心板方案可换时 |
| ❌ | 让高速信号跨分割去"优化" | **接口大概率静默降级** | **绝不允许** |

<Callout type="idea" title="为什么不先砍接口，而是先升层数">
因为**砍接口救不了跨分割**。跨分割是叠层与平面分配的问题，
6 层已经用尽了叠层手段——再砍接口，也腾不出"紧贴完整 GND 的信号层"。
升到 8 层可以增加独立信号层与参考平面，**直接解决根因**。
**接口是软约束，层数是硬约束——硬约束优先。**
</Callout>

### 12.3 如果最终没做到全绿

即使这块板最终没能把双千兆、PCIe、HDMI 全跑通，**这个项目依然完成了考核**，因为你必须亲手经历：

- 叠层设计如何决定阻抗与参考平面
- 高速信号为什么不能跨分割、不能随意换层
- 电源时序错误如何让整板归零
- Bring-up 时如何用有限的仪器把故障范围逐层缩小
- 为什么"能画出来"和"能量产、能长时间稳定运行"是两件事

<Callout type="success" title="考核的真正目的">
这份蓝图的验收标准写得苛刻，但它的价值不在"板子亮不亮"，
而在**你有没有建立起工程判断力**：
知道哪个约束是硬的、哪个是软的，知道出问题时先怀疑什么、先测量什么。

**这才是"能量产、能过认证、能稳定跑五年"的真正含义。**
</Callout>
